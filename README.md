# 星辰路引(網頁版)

原本是一支用 Pythonista(iOS)寫的樂透開獎資料整理 / 版路比對工具,這個專案
把它重新用 HTML / CSS / JavaScript 實作成靜態網頁版,可以直接部署在 GitHub
Pages 上,不需要任何後端或建置流程。

> 這是「全部功能、分階段完成」計畫的進度中的一版:資料匯入、介面骨架、
> 以及 14 個版路模式的**真實運算邏輯**已經可用,其餘功能會在後續階段陸續
> 補上(見下方進度)。

## 運算引擎怎麼做的(重要)

分析邏輯沒有重新用 JS 手刻一遍。原始 `execute_analysis_for_date` 單一函式
就近 5900 行,15 種模式的巢狀迴圈彼此共用、糾纏在一起,手動翻譯成另一種
語言很容易在某個模式悄悄算錯而不自知。

這裡的作法是把原始 Python 運算邏輯(拿掉 `ui` / `photos` / `console` 等
iOS 專屬套件後)整理成 `py/lotto_engine.py`,透過 [Pyodide](https://pyodide.org)
——一個把 CPython 編譯成 WebAssembly、可以直接在瀏覽器裡執行的專案——原封
不動地在瀏覽器內執行。JS 只負責介面、資料上傳、把設定打包成 JSON 傳給
Python、把算出來的文字結果顯示出來。好處是核心運算邏輯跟你原本的 App
是同一份程式碼,不是重新猜寫的翻譯版本。

代價:第一次使用網頁時,瀏覽器需要下載 Pyodide 執行環境(約數MB到十幾MB,
視版本而定),之後會被瀏覽器快取。

**重要修正**:`index.html` 現在是**單一自足檔案**——CSS、JS、甚至整份
Python 引擎原始碼都直接內嵌在檔案裡(引擎用 base64 編碼避免任何跳脫字元
問題)。早期版本是 HTML 另外去讀取 `js/*.js`,結果在「直接雙擊打開」或
某些預覽環境下,瀏覽器抓不到旁邊的檔案,外觀看起來正常但所有互動功能都
會失效(參數設定是空的、按鈕沒反應)。改成單一檔案後,不管雙擊打開、丟到
GitHub Pages,或任何靜態空間都能正常運作,不再需要額外跑本機伺服器。

如果你想修改程式碼:實際原始碼分別放在 `css/style.css`、`js/*.js`、
`py/lotto_engine.py`,改完後執行 `python3 build_single_file.py` 重新
組裝出 `index.html`——不要直接改 `index.html` 本體,下次組裝會被覆蓋。

## 檔案結構

```
xingchen-luyin/
├── index.html               # ⭐ 真正要用的檔案:單一自足網頁,直接雙擊打開即可
├── build_single_file.py     # 組裝腳本:把下面幾份原始碼組合成 index.html
├── css/style.css            # 樣式原始碼(夜空版路主題)
├── js/
│   ├── config.js            # 彩種設定、版路模式清單
│   ├── dateUtils.js         # 日期解析、開獎日計算
│   ├── dataLoader.js        # CSV 解析與驗證
│   ├── engineBridge.src.js  # Pyodide 載入與 JS↔Python 橋接
│   └── app.js                # 狀態管理、畫面渲染、事件綁定
├── py/lotto_engine.py       # 從原始 App 整理出來的運算引擎(見上方說明)
└── README.md
```

`css/`、`js/`、`py/` 底下是給人看、給人改的原始碼;`index.html` 才是
真正要打開來用、要部署的檔案(已經把上面全部內容組裝進同一份自足檔案)。
改了原始碼之後記得跑一次 `python3 build_single_file.py` 重新組裝。

## 本機預覽

直接用瀏覽器打開 `index.html` 就可以(雙擊,或拖進瀏覽器視窗)。因為是
單一自足檔案,不需要跑本機伺服器。

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新的 repository(免費方案的 GitHub Pages 需要 public
   repo 才能直接發布)。
2. 把這個資料夾裡的檔案全部推上去,保持原本的資料夾結構。
3. 到 repository 的 **Settings → Pages**。
4. Source 選 **Deploy from a branch**,Branch 選你的預設分支(通常是
   `main`),資料夾選 `/ (root)`。
5. 儲存後等 1–2 分鐘,畫面會顯示發布後的網址,格式通常是:
   `https://<你的帳號>.github.io/<repository 名稱>/`

## CSV 檔案格式

上傳的 CSV 欄位順序需符合:

```
開獎日期, 期別, 號碼1, 號碼2, ..., 號碼N [, 特別號]
```

- 第一列會被當成表頭自動略過;如果檔案沒有表頭,請自行在最前面加一行。
- 日期格式支援 `YYYY/MM/DD` 或 `YYYY-MM-DD`。
- 「天天樂」沿用原始程式的規則,會自動把日期 +1 天。
- 大樂透 / 六合彩需要在號碼欄位後多一欄特別號;台灣539 / 天天樂則不需要。

範例(大樂透,6 個號碼 + 1 個特別號):

```
開獎日期,期別,號碼1,號碼2,號碼3,號碼4,號碼5,號碼6,特別號
2026/09/08,114000071,3,12,19,25,33,41,7
```

## 關於原始 iOS 版的一點技術說明

原始檔案是用 Pythonista 的 `ui` 模組寫成的 iOS 原生介面,其中包含一段把
App 鎖定在特定裝置才能執行的檢查機制,依賴 iOS 專屬的 `objc_util`。瀏覽器
環境本來就無法執行這類檢查,所以網頁版沒有對應機制,也不會有這個限制。

另外提醒:GitHub Pages 是公開的靜態網站,部署上去之後,前端程式碼(包含
之後第二、三階段會補上的版路運算邏輯)任何人都可以檢視原始碼看到。如果
這個工具會拿來販售或希望邏輯保密,建議在正式對外發布前再考慮清楚。
